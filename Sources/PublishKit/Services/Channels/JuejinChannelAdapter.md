# Juejin pins adapter maintenance

## Scope and request

- Ordinary text/image pins at `https://juejin.cn/pins`, not articles. Deterministic browser operations; never click 发布.
- Receive the unchanged complete ChannelRequest. Optional nonempty title is prepended to raw body with one newline; an empty title adds nothing. HTML is unused; tags and links are ordinary body text. No generated title, rich formatting, topic selection or link-card creation.
- Body required. The observed webpage submit method checks at most 1000 JavaScript UTF-16 code units. Validate the entire composed text before any browser write, conservatively including supplied edge whitespace; emoji can consume multiple units. Do not truncate. No verified image ceiling is asserted; the product editor selects at most six. Verify every supplied attachment rather than slicing.
- Task PNG preparation belongs exclusively to AssetService. Use context.uploadPaths(for:) and preserve original request/source paths; never convert or fall back within this adapter.

## Verified workflow (2026-11-08, ego Lite)

- One task Space and one assigned Page, reused on resume. `/pins` displays the latest feed, with `/pins/new`, `/pins/hot`, `/pins/following` also recognized. A resumed task never navigates away to recover a missing composer.
- Exactly one `.pin-editor .rich-editor[contenteditable="true"]`. The logged-in page has a notification link and composer; logged-out detection uses explicit visible login controls. Actual logged-out/expired-session UI remains to be fault-injected.
- User explicitly authorized clearing existing content before filling. On the first write only, remove existing `.preview-image .delete` controls and `.preview-link .close` link cards, click the editor, Meta+A then keyboard.insertText to replace the complete selection with composed plain text. Verify the full logical result, rather than relying on the action receipt. This also removes the platform-inserted `#新人报道#` topic token. Mark the write attempted before clearing; never clear or insert again on resume, even after an uncertain result.
- Native keyboard.insertText preserves spaces, literal Markdown, blank lines, emoji, hashtags and raw URLs. Read text nodes and DIV/P logical blocks, with sole BR blocks representing empty lines. Ignore zero-length text nodes but preserve all supplied spaces. Do not use innerText (it adds visual newlines). Unknown structures fail verification.
- Do not clear with Backspace followed by paste: the website inserts caret placeholders asynchronously, producing extra leading/trailing newlines. Direct paste also leaves a platform sentinel. page.fill uses an innerText self-check that rejects valid empty paragraphs; the tool explicitly advises click + keyboard instead. Use the proven selection replacement path, not DOM/framework mutation.
- Important platform limitation: the website itself trims edge whitespace in its own state/submit path. Inkpost preserves raw editor input but cannot promise those edge spaces survive the user's eventual publication. Do not mutate framework state to bypass the website.
- Upload input `.pin-editor input#photo[type=file]` accepts PNGs via setInputFiles, one at a time. Attachments are `.pin-editor .preview-image` (the repeated `id=preImage` is NOT unique), with ordered `index` attributes and one decoded img each. Exclude hidden circle recommendation images. Original preview blob URLs remain stable after adding subsequent images; checkpoint ordered URL + dimensions + SHA-256 of decoded pixels. Compare before adding another image or resuming.
- Important platform limitation: files are retained locally in the compose page and actually uploaded only within the user's Publish action. No pre-publication remote upload identity exists. Verify that every attachment is decoded and staged; never claim it has uploaded. Do not invoke private upload/create APIs. This is temporary page state, not a durable draft.
- The unique 发布 button has `active` when ready and an empty class when empty. `.word-counter` exposes `current/1000`. Circle picker explicitly offers 不选择圈子; leave circle choice to the user. A disabled/not-ready button yields an inspectable waiting outcome.
- Mark image addition pending before dispatch. Unknown or missing attachments, changed text/order/images and failed waits preserve the page and require inspection; do not replay uncertain additions. Resume only accepts the original snapshot via DispatchService and the same adapter/Page/prepared PNG batch.

## Acceptance and limits

- Offline tests invoke the actual adapter through a substituted ego executable: first clearing, complete plain-text composition, UTF-16 limits, login/resume, rejection, readiness waiting, cancellation, unknown text/image writes, timeout, user text edits, attachment deletion/reordering/replacement, PNG-only paths and no duplicate writes.
- Generic dispatch contract tests cover full field delivery, same snapshot resume, duplicate prepare, stale identities and channel failure isolation. The main dispatcher has no Juejin branches.
- Opt-in live test: `INKPOST_JUEJIN_LIVE=1`, `INKPOST_JUEJIN_SPACE` = this agent-owned TaskSpace name, Page p1. Generate `/tmp/inkpost-juejin-probe-1.png` and `-2.png` first; run `--filter livePinsWithoutPublishing`. It checks no-title/edge whitespace/Tab/emoji cases, then clears current body/attachments and verifies prepare followed by unchanged resume, stopping before Publish. Only use a page authorized for replacement.
- Live verified: raw text edge cases, two staged PNGs in order, and unchanged resume without duplicate writes, via the real Swift adapter.
- No final-publication acceptance is claimed. Actual logout, expired login, phone binding, platform errors, maximum image acceptance and network faults remain live fault-injection cases. Existing link cards are removed on initial replacement via the verified `.preview-link .close`; a card added during recovery requires inspection and is never silently included. Creation of new link cards is outside this adapter.
