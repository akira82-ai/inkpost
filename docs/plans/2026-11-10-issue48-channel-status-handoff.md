# #48 渠道状态、登录恢复与任务交接开发计划

**Goal:** 将已确认原型落地为原生界面：渠道标签显示四种无背景状态图标，仅登录提供恢复；任务结束后交还 Space，用户前往成功后恢复新稿。

**Architecture:** 沿用 DispatchModel、DispatchController、DispatchService 和渠道适配器。领域状态与 UI 图标分开，View 不调用浏览器。保留任务输入快照、Space/Page 映射和旧事件隔离，不引入第二套调度系统。

**Tech Stack:** macOS 14+、SwiftUI、Swift Package Manager、Swift Testing、ego Lite 官方接口。复用 SF Symbols、ProgressView、现有页面导航与恢复契约，无新增第三方依赖。

## 已确认范围

- 填写中、填写成功、需登录、其他问题在渠道标签右侧以图标显示；异常图标无背景色块，提供悬停说明、键盘操作和无障碍标签。
- 编辑时标签负责渠道选择；任务中选择冻结，登录和问题图标是独立操作入口，不嵌套 Button。
- 登录图标打开本次任务该渠道的原 Page；问题图标仅打开页面，不自动重试或重置稿件。
- 有待登录渠道时大黑按钮为「我已登录，继续」，逐个恢复登录等待渠道；已成功渠道不重复填写，仍未登录的保留等待。
- 保留「跳过，手工处理」结束剩余登录等待；底部汇总与次要操作同字号、行高、居中同排。
- 全部填好后大黑按钮为「已填写，需要你手工发布」；存在问题则为「去查看」。
- 全部自动流程结束（含失败、跳过、取消）后，对已有 Space 标记完成并交还；等待登录不属于任务结束。
- 最终主按钮打开本次任务 Space，确认成功后归档并清空正文、标题、图片，保留渠道选择。打开失败保留原稿。
- 不实现消散动画、普通异常重试、新平台或真实自动发布。

## 1. 先验证浏览器控制权边界

- 在本地 fixture 验证 task.handOff、takeOverTaskSpace、finish({keep}) 的状态、Page 标签与完成后重开行为；不对真实平台发布。
- 重点核实用户登录时其他 Page 是否允许继续自动操作。目前 openChannel 拒绝 activeAttempts，handoff 是 Space 级操作，不能直接删除保护。
- 若只能 Space 级交还：先完成当前安全操作、保存尚未执行渠道，再交还；用户确认后接续原任务。该限制会影响“登录期间其他渠道照常执行”，需将实测事实和可选方案报告用户，确认取舍后实施相关分支。
- 验证完成后 Space 由用户拥有，后续只能根据显式点击重新打开；finish 后 Page 标签可能失效，不可继续用旧句柄执行。

出口：确定可执行的控制权方案，以及完成后保留页面、重开 Space 的正确接口。原型不能替代此验证。

## 2. 明确状态与任务收尾

- 先补现有控制器测试，覆盖等待登录不算失败、不发最终完成通知，以及正常/异常任务统一结束。
- 复用现有 TargetPhase，只有现有语义不足才添加必要任务状态；四个 UI 图标由渠道真实状态派生，不把取消或未执行伪装为成功。
- 拆开“本轮自动执行停止”“等待登录”和“任务最终结束”，禁止存在执行中渠道时提前完成 Space。
- 终态统一执行一次完成与交还；失败明确记录，不吞掉失败或伪报已交还。

出口：成功、部分失败、全失败、跳过、取消、等待登录的状态测试通过。

## 3. 实现渠道导航与登录后继续

- 为渠道图标提供 openChannel(platform) 控制器入口，复用已有原 Page 定位，导航不改变填写结果。
- 实现统一继续动作，捕获本次等待登录渠道快照，以 resumeAfterUser 依次恢复，沿用原输入、原任务和原页面。
- 只允许登录等待进入该恢复入口，不根据英文报错或一般超时猜测未登录。
- 导航、继续、跳过、收尾互斥；每个异步结果检查 taskID/attemptID，重置后旧结果不得回写。
- Page 缺失、Space 失效、控制权无法恢复分别明确反馈，保留内容，不静默新建页面或任务。

出口：多个渠道分次登录、重复点击、旧事件、缺失页面与未知操作结果测试通过；已成功渠道调用次数不增加。

## 4. 落地原生界面

- 使用 SF Symbols 线性对勾、登录、问题图标和小尺寸进度控件；无异常背景块，颜色与形状共同区分。
- 标签整体保持等宽；在现有 420pt 窗口中核对三列布局与长名称，不挤压图标点击区域。
- 大黑按钮始终保留，按任务操作状态显示发布、填写中、我已登录，继续、检查中、最终前往。
- 移除旧按钮文案和与新流程冲突的展示，保留内部诊断日志；不扩大到其他视觉重构。
- 同步原生视图测试，检查四态、长名称、VoiceOver、键盘焦点与减少动态效果。

出口：所有原型场景可由原生视图测试或受控 fixture 重现，状态图标点击目标明确。

## 5. 完成后导航与新稿

- 最终按钮统一打开任务 Space，不再默认定位第一个异常 Page；渠道图标仍负责具体 Page 导航。
- 扩展现有归档与清空路径，使异常、跳过等已结束任务也能在成功导航后恢复新稿。
- 导航失败保留内容、图片、任务身份和再次点击入口；成功时保留渠道选择。
- 通知导航不得清空其他任务；等待登录、恢复和进度更新不得再次自动隐藏窗口。

出口：各终态的导航成功重置、失败保留与通知隔离测试通过。
