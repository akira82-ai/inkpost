# 简约模式开发计划

关联：GitHub Issue #2。设计依据：`prototypes/inpost-prototype-简约模式.html` 末尾需求清单和 UI 规格。

## 当前事实与范围

现有 SwiftUI / macOS 14+ / SPM 栈已拆出 DispatchModel、DispatchController、DispatchServicing 与 Views，存在控制器测试；复用这些实现，不重建架构。当前 App 只有完整窗口，素材为路径数组，服务每渠道创建独立 Space，控制器尚无单渠道恢复。HTML 是交互演示，不是原生能力证明。

本次交付菜单栏常驻与简约填写流程；原型中的海外平台不代表真实支持。最终状态为已填好，用户在浏览器亲手发布，不实现自动发布或产品层发布回执跟踪。CLI fixture 回执工具可继续用于内部验证。

## 影响面清单

- PublishFlowApp：仅组装依赖和场景，同一个 Controller / Model 供两种界面使用。
- Views：菜单栏浮层、简约编辑、图片网格、渠道栅格、状态主按钮、完整窗口入口、文件选择与粘贴桥接。
- DispatchModel / Models：附件、执行快照、当前渠道、每渠道原因与任务上下文；沿用 TargetPhase，不另建重复任务枚举。
- DispatchController：输入校验、稳定快照、状态汇总、单渠道继续，避免把部分失败误报为全部已填好。
- Services / DispatchSettings / EgoBridge：素材处理、渠道偏好、工作区会话、恢复与提醒能力。
- Tests / README / AGENTS：协调测试、使用说明与职责规则随代码同步。

## 1. 基线与状态契约

- 先运行 swift build、swift test，记录已有失败，不修改现有未提交工作；开始开发时新建 codex/ 前缀分支，不自行提交或推送。
- 核对 TargetPhase 映射：pending → 等待开始，preparing → 正在填写，awaitingConfirm → 已填好，needLogin / failed 等 → 需要您手工处理。Presentation 文案属于 View。
- 在任务开始时冻结标题、正文、图片顺序、渠道；防止异步执行混用编辑中的内容。
- 明确部分完成汇总：仍有执行则填写中；执行结束存在异常则需要手工处理；全部校验通过才已填好。
- 验收：注入假服务覆盖全成功、部分失败、需登录及重复点击，不依赖真实浏览器。

## 2. 菜单栏与简约 UI

- 优先使用原生 MenuBarExtra 窗口形态；验证编辑、外点收起和文件选择行为，如不能满足，再使用封装在 Views 内的 AppKit 浮层桥接，不提前自建窗口框架。
- 每次弹出简约界面时默认聚焦正文，不清空或全选已有文字，不持续抢焦点（#35）。
- 420pt 宽、圆角 14pt、左右内距 18pt；正文固定六行可见高度（可视区 151pt，加工具区整体 181pt），不扩展，超出后内部滚动，不提供手动缩放，字数位于框内右下角；标题与正文分别清空。
- 右上角展开入口打开完整窗口；关闭窗口不退出任务；两种界面共享状态，收起后保留当前输入。永久退出保留原生退出入口。
- 渠道 4 等列、8pt 间距、32pt 高；420pt 面板内每个宽 90pt，末行不拉伸；固定顺序、无勾、无选中动画，记住上次选择。
- 颜色、字体、阴影按 HTML 规格实施，实际显示器复核可读性和小屏边界。
- 验收：不接真实浏览器 即可完整验证输入、切换、外点收起和恢复；View 不直接操作存储、浏览器。

## 3. 图片附件

- View 负责选择器和粘贴接入，Controller 调素材服务执行校验与导入；统一附件来源，不在 View 内读写文件。
- 最多 6 张，单行等宽正方形、8pt 间距与圆角；末尾同尺寸添加格，满额隐藏；支持预览、移除、排序。
- 粘贴图片导入受控临时目录；按文件字节 SHA-256 去重，不宣称能识别压缩或裁切后的同画面；并发导入串行化，先去重再计算剩余额度。
- 简约与完整界面共用附件顺序；错误提示在当前界面中央显示。
- 验收：本地与粘贴混合添加、批内/跨批重复、超限、移除后重加、排序后执行顺序一致；明确临时文件生命周期。

## 4. 执行、异常恢复与工作区

- 先核实 ego Lite 官方能力，再实现一次任务一个 Space、各渠道显式绑定 Tab；禁止依赖当前活动 Tab。登录辅助页与主编辑页关联保存。
- 为 DispatchServicing 增加有必要的任务上下文、进度事件、打开工作区与恢复契约，复用确定性浏览器执行入口，GUI / CLI 不复制执行逻辑。
- 需要手工处理时保存具体渠道、原因和恢复点，其他渠道继续；用户继续后重新检测登录/验证和页面内容，不盲目重填或重新上传。
- 主按钮：开始填写 → 正在填写具体渠道（向上滚动）→ 已完成，前往发布；异常时前往处理 ↗。
- 混合结果在渠道级提供已填好内容入口和异常继续操作，不能用全局按钮隐藏部分失败。
- 当前 HTML 演示循环只供设计查看；正式按钮由真实当前渠道驱动，非固定计时轮播；支持减少动态效果。
- 填写结果独立校验，先解决正文截断 / HTML 未进入任务的问题，再验收长文章；这是独立可靠性改动，不伪装成纯 UI 搬迁。
- 验收：fixture 中检验显式 Tab 操作、内容完整、失败恢复及不重复操作；不在真实平台发布测试内容。

## 5. 后台提醒与最终验收

- 收起后任务继续；需要手工处理和全部已填好时给出提醒。系统通知需按系统权限接入，拒绝授权时仍在菜单栏和界面呈现状态，不谎报已通知。
- 产品不追踪已发布状态；完成按钮只打开工作区，不点击平台发布按钮。提示词限制不是安全边界，任意 JS / 点击能力需单独审查执行约束。
- 完成后允许明确开始新一份内容；仍有未完成渠道时不静默覆盖任务上下文。
- swift build、swift test 通过，ego Lite 可用时运行 fixture smoke；手工验证键盘、减少动画、小屏、长内容、多图、登录恢复、部分异常、关闭窗口后任务继续。
- 同步 README / AGENTS 和原型已实现标记，海外候选渠道保持能力标签，不扩大真实支持声明。

## 实施顺序与交付边界

按 1 → 2 → 3 → 4 → 5 推进，每阶段有可检查结果。阶段 2–3 可用假服务演示；阶段 4–5 完成后才能宣称原生端到端可用。当前仅完成计划与 Issue 更新，尚未实施或运行上述验收。

## 原型逐项对齐记录

- 以原型最终 CSS 和文末 UI 规范为准：抽取共享颜色与字号，重做简约界面的头部、内容和操作区间距，采用实际内容高度、小屏内部滚动、正文 23.4pt 行高及固定 28pt 字数避让区。

- 渠道使用现有展示项、配色和固定顺序；统一四列等宽（#33），不使用模拟平台填充正式渠道。简约渠道列表根据注册状态隐藏未接入项，不展示占位渠道。

- 完整工作台使用原型的左侧导航、中央编辑器和右侧渠道卡片；模型配置及其设置入口已移除。投递记录当前只展示本次运行日志，不假称已支持历史持久化；账号状态不伪造已登录。
- 原生 NSTextView 回归覆盖 PNG/TIFF/JPEG、普通文字、只读保护及 Finder 图片文件粘贴；离屏原生预览核查 420pt 宽度、长正文和单行六图。真实窗口交互仍需手工复核，工具超时不能视为验收通过。
